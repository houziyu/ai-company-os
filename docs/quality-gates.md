# 验收与质量门禁

本文件是需求清单，不表示工具已经实现或测试已执行。阶段报告必须给出实际证据。

## 全阶段公共门禁

- 分配需求有真实实现，依赖前置阶段已核实；无假按钮、无伪造供应商调用。
- schema/接口/枚举/前端文案一致；正常和失败路径都有验证。
- 所有者认证与对象权限有效；秘密不泄露；预算/审批/状态由服务端约束。
- 数据库迁移通过；升级不清空数据；已有验收回归通过。
- 相关检查命令真实执行并保存摘要；未执行明确标注理由。
- 填写阶段验收和交接，不将“代码写完”视为“阶段完成”。

## UI 门禁

1. 使用唯一 token 和公共组件；新增页没有散落 hex、任意按钮高或第二套组件库。
2. 在 1440×900、1024×768、390×844 三视口截图并检查；360px 宽和 200% 缩放做可用性检查。
3. 截图至少含默认、空、加载、错误、禁用和关键提交状态；执行页增加运行中/失败/成功，审批页增加无权/预算不足/高风险。
4. 普通文字对比 ≥4.5:1、必要控件边界/焦点 ≥3:1；实际组合检查包括 hover/active/标签。不能只查主色一组。
5. 键盘可完成登录、创建项目、编辑模型、审批；弹窗焦点正确，关闭返回触发点。
6. 手机触达 ≥44；页头操作可换行；弹窗不超视口；正文不被固定栏遮挡；日志和表格仅自身滚动。
7. 状态有文字，不依靠颜色；图标按钮有名字；错误可理解并保留用户输入。
8. SSE 重连、请求失败、旧数据标识、重复点击均正确；模型文本按不可信内容处理。
9. 对设计样张的对齐只检验真实实现后截图，不把静态样张当成完成产品的证明。

## 测试组织

后端：领域规则单元测试 + PostgreSQL 集成/事务测试 + API 契约测试。
前端：公共组件交互测试 + 关键业务端到端测试 + 截图人工检查。
执行器：真实容器集成与故障注入，生产策略与测试策略一致；避免运行未限制的恶意样例。
模拟模型只用于协议和失败控制；独立标识真实模型验收，不能混为一种统计。
漏洞修复应有能复现原问题的回归测试；测试不依赖网络偶然成功或固定 sleep。
耗时长的外部测试单独标记，不能通过 skip 全部隔离测试后宣称安全验证成功。

## 完成定义

通过 = 需求实现、相应门禁实际执行通过、文档匹配、无阻断性问题。
部分完成 = 缺前置条件或外部验证；明确剩余项，不进入依赖该项的后续验收。
失败 = 已执行检查不满足目标；保留日志和修复计划。
发布前未知的高风险权限/数据一致性问题视为阻断。性能指标需有环境、负载、测量方法，禁止凭感觉写“高性能”。
