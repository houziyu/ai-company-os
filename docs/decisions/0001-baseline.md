# ADR-0001：开发前技术、设计与交付基线

日期：2026-10-29。状态：本次文档任务采用的 v1 基线，后续变更留档。

## 背景与选择

用户希望先完成全部约束，再交给其他 AI 分阶段开发。产品目标与 delegated/bounded/template 已由用户确定；Docker Compose 为明确部署要求。FastAPI + Vue 路线在讨论后被纳入阶段计划。

本次为避免接力开发产生视觉分歧，选定 Element Plus 作为基础组件库、浅色主题、蓝色主操作、统一 32/40/48px 控件规格。此项是本轮设计决定，不声称用户之前已指定该组件库。
使用 AGENTS.md 作为共享规则源，CLAUDE.md 仅阅读入口，免去复制生成器和同步误差。
技术基线详见 architecture.md，数值详见 design/design-tokens.json。

## 本次修正

旧 PRD 的 SQLite/纯标准库/原生前端方案不再作为实施依据。初始草稿不算已完成里程碑。
现有八阶段计划保留顺序；阶段 01 增加 token、组件样例和布局基线验收，其后每阶段都要做相应 UI 检查。
开源方向已确定，但具体许可证尚待发布前确认；旧 PRD 的 Apache-2.0 只是早期建议，不能当作已授权许可证声明。

## 保留的开放事项

- 第三方插件协议与信任模型，首版只留扩展边界。
- 实际模型能力、价格、兼容版本，须运行时验证。
- 具体依赖版本和 Python/pnpm 管理工具，阶段 01 验证并锁定。
- 多租户、暗色主题、多语言界面、生产部署工具，均未进入当前八阶段必做范围。

这些事项不阻止按当前基线实现前置阶段。UI 布局和普通实现细节按规范直接落实，无需重复征询。
