## 背景

阶段 02 需要新增公司、组织与模型配置。有三处若按直觉实现会在后期难以纠正：

1. **公司唯一性**：单公司是产品前提，但阶段 01 的 `platform_state` 已用“固定主键 + `id = 1` 检查约束”实现了单例行。
2. **岗位版本与并发编辑**：岗位职责要保留历史版本；同时组织页允许编辑，两个浏览器可能同时保存同一岗位。
3. **模型能力与时延**：供应商都声称“OpenAI 兼容”，但兼容协议不等于支持 JSON 输出；“测试连接”会消耗 Token，重复自动重试会放大费用。

## 决定

**单公司用固定主键 1 + `CHECK (id = 1)`**，与 `platform_state` 同一手法。唯一索引会允许缺号（2、3……），固定主键让第二行在物理上不可能存在。迁移**不**插入公司行：公司只在向导成功后存在，`GET /company` 在向导前如实返回 404，而不是返回一个空壳对象。

**模板是只读参考数据，实例化是复制**。`company_template_positions` 由迁移种入 5 行（template_key + version + code 唯一），运行期从不写入；实例化时复制到 `positions` + `position_versions` + `agents`。因此后续修改模板不会改写已有公司的组织；`companies.template_key/template_version` 记录“这家公司由哪个模板生成”。

**岗位版本与并发令牌分离**。`positions.current_version` 只表示职责快照号（追加式，`position_versions` 永不更新）；`positions.row_version` 是每次成功编辑都递增的乐观锁令牌。若用 `current_version` 兼作乐观锁，两个仅修改岗位名称的并发客户端会各自看到相同版本号并互相覆盖，因为改名不追加版本。实施中被测试发现（`test_position_stale_version_is_rejected` 初期失败），故拆为两列。

**职责双层：岗位版本 + 员工覆盖**。员工覆盖写入 `agents.duty_override`，每次变更（含清除）追加 `agent_duty_override_history`。清除覆盖写一行 `duty = NULL` 的历史，而不是删除旧记录——“回到岗位版本”本身是一次可审计的变更。

**管理关系是单向边，不是权限来源**。`agents.manager_id` 自引用外键，`CHECK (manager_id <> id)` 拒绝自环；跨层环由服务层在同事务内、锁定全公司员工行后计算后代集合判定。授权代码路径完全不读取 `manager_id`，员工也不是认证主体（阶段 02 无员工账号）。因此“汇报关系不授予资源权限”是结构性的，而非依赖后续开发者自觉。

**员工身份不可删除**。没有删除端点；`PAUSED`/`ARCHIVED` 是状态变更，`employee_code` 与全部历史保留。所有外键 `ondelete="RESTRICT"`，没有级联删除路径。

**密钥只存引用名**。`providers.secret_ref` 存**环境变量名**（正则 `^[A-Z][A-Z0-9_]*$`），`secret_source` 固定 `ENV`，为将来接入 Compose secret 保留语义位置。没有任何列可以存密钥值；没有返回密钥的端点；Base URL 拒绝内嵌账号密码（防止把密钥塞进 URL 落库）。`secret_configured` 在每次读取时由进程环境计算，因此“界面只显示是否配置”不是 UI 约定而是数据模型约束。

**保存与探测是两个命令**。配置端点不触网；探测端点只用已持久化的配置，因此“测试”永远不会应用未确认的编辑。探测：恰好一次 HTTP 请求（`model_probes.call_count <= 1` 约束），无自动重试、不跟随重定向、不切换备用模型；超时在 1–120 秒夹取；错误映射为稳定 `ProbeErrorCode`，供应商响应正文与回显的密钥被丢弃。即使返回无效 JSON，只要请求到达供应商就登记用量（`provider_usage_records`），未知用量写 `NULL` 且 `usage_known=false`，不记 0。

**模拟传输只存在于测试进程**。`create_app(probe_transport=...)` 是唯一注入点；生产调用不带 transport，部署中不存在切换到演练的开关，符合“真实模式不得静默降级为演练”。

## 备选与取舍

- *单公司用唯一索引或配置项*：无法在数据库层面阻止第二家公司；固定主键更严格。
- *把公司字段加到 `platform_state`*：会把“平台是谁的”与“公司是什么”绑在一起，且该行由迁移预置，无法表达“公司尚未创建”。
- *组织树用邻接表 + 递归 CTE 存环检测*：可行，但写时校验更早失败、错误信息更准确，且锁内校验能挡住并发重入。保留邻接表。
- *员工与岗位合并成一张表*：会丢失“岗位定义”与“个人覆盖”的区分，也无法在换人时保留岗位职责版本。
- *密钥加密后入库*：需要密钥管理服务与轮换流程，超出本阶段；环境变量/Compose secret 已满足“不进入 Prompt、浏览器、日志与审计”的要求。
- *探测失败自动重试*：会成倍放大 Token 消耗，且掩盖供应商稳定性问题。改为单次 + 明确提示 + 用量登记。

## 影响与迁移

- 新增 12 张表与 1 个迁移 `7b41c9d2f0aa`；`users.role` 约束未改，未引入员工账号。降级会删除阶段 02 全部表与数据，仅在无公司数据时安全。
- `GET /auth/setup-status` 增加 `companyInitialized`/`companyName`，是唯一被扩展的既有响应；旧客户端不受影响。
- `docs/design/design-tokens.json` 的 `color.disabledText` 由 `#64748B` 改为 `#475569`：实测禁用按钮文字在原组合下只有 3.86:1，低于 4.5:1 门禁；禁用控件保留形状（不整体降透明），因此文字必须自身达标。这是本阶段唯一的视觉数值变更，理由已同步到 UI-SPEC。
- Compose 增加 `DEEPSEEK_API_KEY` 透传（默认空）。空值即“未配置”，不是错误。
- 依赖：`httpx==0.28.1` 从开发依赖移入运行时依赖（适配器在生产镜像中需要它）；版本不变。

## 追加（2026-10-30，独立质检修复轮）

独立质检证明以下三处原始设计不足，本 ADR 的决定随之收紧：

1. **“外部响应只有错误正文危险”是错的。** 供应商可以把凭据回显在 `model` 字段，原实现会把它写入 `resolved_name` 并返回浏览器。现在**所有**来自供应商、将被持久化或展示的字段（模型标识、Token 数）在进入业务层前统一做类型、长度、目标列范围与当前凭据筛查；不合格值丢弃但保留调用记录。
2. **“调用前写入行”不等于“调用前提交行”。** 原实现只 `flush()`，进程死亡会连同请求事务一起丢掉证据。现在意图行在独立短事务中提交为 `PENDING`，结果在第二个事务写回；中断即“结果与用量未知”，不推断、不重发。
3. **探测证据必须归属于产生它的配置。** 新增 `config_fingerprint`（kind/baseUrl/secretRef/timeout 的哈希）与供应商/模型 `version`。配置变化使当前能力失效但保留历史；更新必须携带读取到的版本，否则 409。

另有两处语义收紧：用量改为按维度记录完整性（`prompt_tokens_known`/`completion_tokens_known`，`usage_known` 只在全维度已知时为真）；配置的超时改为覆盖连接、读取、解析的总预算并限制响应体积，因为 `httpx` 的读超时只是单次读。

新增决定：**`expectedVersion` 必填**。可选版本等于允许“我不知道版本但仍然覆盖”，正是 R7 的缺陷；代价是调用方必须同步，本仓库只有前端与验收脚本，已改。**不新增配置历史表**：本阶段只需回答“证据是否属于当前配置”与“表单是否过期”，旧探测行已含其指纹。

## 验证与回退

### 追加（2026-11-02，第二版复审修复）

- **证据归属检查使用锁内刷新后的数据库状态。** 完成探测时依次锁供应商、模型，并刷新 ORM 已加载对象；配置更新遵循相同顺序。使用 `FOR NO KEY UPDATE` 保持非主键更新互斥，同时允许历史插入的外键检查，避免与意图/用量写入相互等待。网络调用期间不持有这些配置锁。迟到结果保留探测、用量和审计，只禁止改写新配置的能力证据。
- **空指纹不代表证据有效。** 模型中心、员工分配、组织页统一要求双方非空且相等。新增数据迁移 `8c24a71d9e03`，按冻结算法回填供应商指纹，清理无法归属的当前能力字段；已匹配证据和所有历史保留。迁移须在线执行；降级保留修复后的数据，不重新制造无效能力状态。
- **总截止时间能中止网络等待。** 适配器改用现有 httpx 的异步客户端与可取消超时作用域，覆盖响应头和响应体，取消后关闭连接，不留下继续请求的后台线程。同步 API 保留 `probe()` 入口；已有事件循环的内部调用方使用 `await probe_async()`。测试传输需支持异步接口；不新增依赖、不改变平台技术栈、无自动重试。
- **可编码性属于持久化边界校验。** 模型标识必须能编码为 UTF-8；孤立代理字符被丢弃，但有效用量与调用证据照常写入，包括输出 JSON 无效时。
- **成功写响应立即成为前端版本来源。** 员工资料保存成功即应用响应，后续组织/模型刷新失败不回退版本或覆盖草稿。移动抽屉使用现有语义宽度 token 在窄屏映射为 100%，保证部分保存提示可读。
