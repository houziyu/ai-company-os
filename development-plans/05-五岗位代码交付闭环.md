# 开发计划 05：五岗位协作与首次真实研发交付

## 可直接交给 AI 的任务

请把已有组织、模型、任务、预算和执行器连接起来，实现五岗位协作。此阶段完成后，用户应能输入一个有边界的小型代码目标，拿到可验证的代码产物。

## 本阶段结果

目标 → CEO 计划 → PM 验收契约 → 开发实现 → QA 隔离验证 → DevOps 打包 → 用户下载。任何阶段失败都留下明确原因和独立执行记录。

## 实施范围

1. 首批支持 Python 标准库模块/命令行小项目；界面明确支持范围。对超范围目标要求缩小或标记阻塞，不能静默替换成固定示例。
2. CEO 输出范围、工作计划和角色分工；PM 在开发前确定接口契约、验收条件和测试；开发只修改授权源文件。
3. QA 基于 PM 验收及实际隔离测试作出评审；DevOps 生成运行说明、交付清单和验证摘要。确定性的打包步骤不必额外调用模型。
4. 每岗位使用其绑定模型和职责构建上下文；注入平台规则、任务资料与必要上下游产物。不得共享所有历史、秘密或无关项目资料。
5. 保存角色、岗位版本、模型、Prompt 模板版本、步骤结果、调用用量、工具记录与产物；更换模型不改写历史执行。
6. 真实模式调用配置的兼容 API；演练模式使用固定案例且持续显示演练标识，两者路径清楚。
7. 流式文字可作为进度展示，但结构化结果必须完整验证后才能改变业务状态。模型输出不能直接将任务置为成功。
8. QA 失败后可进行最多两轮已授权范围内返工；每轮保留证据并重新校验预算。验收标准不得由开发为了通过而降低。
9. 返工耗尽或范围变化进入 BLOCKED/等待决策；不无限调用。缺少具体输入时给用户明确问题和补充入口。
10. 成功门禁：产物存在、结构有效、至少一项真实验收、测试通过、QA 通过、哈希清单完整。

## 验收

- 演练流程通过真实隔离测试，并产出可下载文件；明确不是模型自主生成。
- 使用模拟 API 覆盖所有岗位协议及错误路径，返回伪成功文本不能绕过门禁。
- 在已提供密钥及测试预算的环境中，选择三个不同的小目标完成真实 API 验收；记录实际测试和用量，不允许三个目标都返回同一固定模板。
- 密钥缺失、无效 JSON、超时、预算不足、QA 拒绝均能正确阻塞/失败。
- 人为让开发产出错误实现，独立测试必须发现错误；修复后旧失败证据仍保留。
- 暂停公司后不会开始下一调用；重试不会重复计费记账或覆盖旧产物。

## 交付与边界

交付真实协作流程、执行时间线、产物下载、示例目标和验收报告。没有真实密钥时完成其他开发，但把“真实 API 三目标验收”明确列为待验证；不能宣布全部验收通过。
