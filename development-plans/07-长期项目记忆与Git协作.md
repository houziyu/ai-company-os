# 开发计划 07：长期项目、任务依赖、记忆与 Git 工作区

## 可直接交给 AI 的任务

请把阶段 06 的单次任务闭环扩展为可持续推进的项目，支持任务依赖、项目记忆和受控 Git 代码协作。

## 本阶段结果

同一项目可以跨多天、跨服务重启继续；后续任务能够使用已验证经验和前序产物，在独立开发分支中修改项目，并留下差异与验证记录。

## 实施范围

1. 任务依赖 DAG：拒绝环，依赖未完成不得启动；失败依赖使下游阻塞；记录依赖产物版本，变化后重新检查。
2. 有限并行：只运行相互独立任务，遵守公司/项目并发和预算限额；共享仓库写操作有明确锁或独立工作区。
3. 持久检查点和事件消费者游标；能明确区分“从可安全重试步骤恢复”与“未知外部副作用需人工确认”。
4. 四类记忆：工作、任务、项目、组织。记录来源、作用域、版本、状态和证据。
5. 检索只返回当前授权项目与已批准组织知识；限制数量、长度与 Token。过期知识不默认进入上下文。
6. 任务总结先成为候选知识；组织知识晋升经过评审。原始文档和检索内容作为不可信数据处理。
7. 支持用户明确选择的本地 Git 项目导入；每任务独立分支/工作区，产物记录基准提交与 diff，不直接写主分支。
8. 合并冲突进入待处理状态，不擅自丢弃用户修改；确认依赖版本后再验证候选合并结果。
9. 为现有 Python 多文件项目提供固定可配置的构建/测试配置；依赖来自所有者预先授权的镜像，不让 Agent 任意安装包。
10. 提供项目页：目标、里程碑、依赖、预算、阻塞、知识和代码差异；明确可暂停与恢复。

## 验收

- A→B 依赖下，A 未完成时 B 不运行；独立任务 C 可在额度内并行。
- 服务重启后审批等待、预算、队列、记忆和产物完整保留。
- A 产物版本变更能触发 B 的复验，而不是沿用旧通过记录。
- 项目 A 的私密资料不会进入项目 B 的模型上下文。
- 过期/未批准组织知识不会自动被全公司检索。
- 在一个已有小型 Python 仓库中完成至少两个有关联的代码任务，交付 diff 和回归测试证据。
- 用户未提交修改不会被覆盖；冲突有明确阻塞记录；主分支不被自动合并。

## 交付与边界

交付项目持续运行能力、DAG 调度、记忆检索、Git 工作区管理和恢复测试。不扩展到多租户、任意语言生态、插件市场或自动生产部署。
