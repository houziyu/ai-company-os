# 开发计划 04：工具网关、隔离运行与产物证据

## 可直接交给 AI 的任务

请实现受限工具网关和代码执行器，先支持 Python 标准库小项目。目标是让实际代码和测试在隔离环境运行并产生真实证据。

## 本阶段结果

控制台提交一个固定代码样例，能够看到隔离测试结果并下载源码、测试日志和哈希清单。失败和超时会如实呈现。

## 实施范围

1. 定义 ToolSpec、ToolCall、ToolResult、ArtifactManifest；输入输出结构化，调用关联任务、执行、角色和授权。
2. 有效权限由公司策略、岗位能力、项目范围、任务范围交集计算；在执行时再次校验租约和权限，不能只在创建时检查。
3. 内置工具先限于工作区读写、运行白名单验证命令、收集产物；模型不得提供任意宿主 shell 命令。
4. 每次执行独立工作目录；禁止绝对路径、目录穿越、符号链接逃逸与超限文件；失败结果也可归档。
5. 执行器通过内部受认证接口接收结构化任务；API 和 Worker 不挂载 Docker socket，模型不能直接调用容器管理接口。
6. 明确执行器的 Docker 权限方案：若使用宿主 socket，只交给专用执行器，执行器自身仍属于高信任组件；限制镜像、挂载和参数。记录该方案的宿主风险，不能声称代理接口消除了 Docker 管理权限风险。
7. 任务容器默认无网络、非 root、丢弃 capabilities、只读根、受限临时空间、CPU/内存/PID/时间/输出限制。禁止挂载数据库、密钥、宿主根目录和 Docker socket。
8. 验收测试与生成代码分开保存；开发角色不能覆盖验收文件。测试代码同样必须隔离执行。
9. 归档源码、测试、测试数量、退出码、日志、运行镜像标识、时间和 SHA-256 清单；下载接口验证对象归属。
10. 执行器不可用时任务 BLOCKED，不回退到宿主执行；超时清理仅限本系统创建的任务容器。

## 验收

- 正常样例真实运行并通过；错误代码、断言失败、零测试、全部跳过均不能通过门禁。
- 无限循环被超时终止；输出洪泛受限；不可突破资源限制。
- 网络访问、越界路径、读取平台密钥、修改验收文件被拦截或在隔离环境中失败。
- 执行器离线时返回可理解的阻塞状态。
- 并发任务工作区互不覆盖；产物可下载且哈希可复算。
- Docker/执行器真实集成测试必须运行；未运行不能只用 Mock 宣称完成隔离验收。

## 交付与边界

交付执行器服务、Compose 配置、工具协议、隔离策略、攻击样例测试和证据页。首版不支持任意依赖下载、生产部署、外部发送或第三方插件。
