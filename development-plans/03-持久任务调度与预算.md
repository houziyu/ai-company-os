# 开发计划 03：任务状态机、Worker、事件与预算

## 可直接交给 AI 的任务

请实现可以重启恢复的任务内核。使用确定性测试处理器验证流程；本阶段不接入自主代码执行，不把模拟结果描述为真实模型产出。

## 本阶段结果

用户创建项目和任务，任务由独立 Worker 领取；页面实时显示进展。重复请求、预算不足、暂停或进程重启都不会破坏任务记录。

## 实施范围

1. 建立 Project、Task、Execution、ExecutionStep、Event、Message、BudgetAccount、BudgetReservation、UsageLedger。
2. Task 与每次 Execution 分离；重试创建新执行，保留旧证据。任务状态至少含 QUEUED、RUNNING、WAITING_APPROVAL、BLOCKED、SUCCEEDED、FAILED、CANCELLED、INTERRUPTED。
3. 状态迁移由明确的服务端规则控制；不接受任意 PATCH state。
4. PostgreSQL 事务领取任务，带 worker ID、租约、心跳、执行 fencing token；旧 Worker 在失去租约后不能写结果或继续启动工具。
5. 所有付费调用前原子预留公司/项目/任务额度，调用后结算。第一版用 Token 作为硬限制；显示输入/输出及保守估计，币值估算不伪装成账单。
6. 创建任务、预算预留、事件写入使用同一事务。幂等键有作用域和内容摘要，重复键不同请求应报冲突。
7. 全公司暂停阻止新调用；取消采用明确的协作式停止。正在外部执行的步骤记录停止结果，不假装立即取消。
8. 将阶段 02 模型探测纳入公司预算，缺失密钥时不实际扣费；超时或供应商用量未知时保守预留并标记待核对。
9. 事务事件日志用于通知与补读；SSE 支持事件 ID 和断线续读；结构化消息包含 sender、receiver、type、task、correlation、payload。
10. 重启恢复排队任务；运行中未知副作用的步骤标记 INTERRUPTED，禁止盲目重放。只自动重试明确可重试且幂等的步骤，默认次数有限。

## 验收

- 同一请求提交两次，只出现一个任务和一笔预留。
- 两个 Worker 同时抢任务，只允许一个有效执行持有者。
- 两任务同时争抢不足预算，只批准可用额度内的请求，余额不出现负数。
- Worker 中途退出后，任务可被识别为中断；旧 Worker 迟到结果不能覆盖新状态。
- 重试有独立执行 ID；历史日志和账本不被覆盖。
- 公司暂停后没有新模型/工具调用；SSE 重连能够补读事件。
- 模拟失败、取消、超时均正确处理预算，不重复释放或重复记账。

## 交付与边界

交付任务看板、执行详情、预算展示、Worker、状态机、事件接口、并发与故障测试。该阶段演练处理器必须标为测试/演练，不能作为研发交付。
