# 开发计划 01：工程骨架与 Docker Compose 部署

## 可直接交给 AI 的任务

请结合《00-总纲与交接规则》实施第一阶段。建立 FastAPI + Vue 3 + PostgreSQL 工程，优先交付可启动、可登录、可维护的系统基础。

## 本阶段结果

执行 Compose 启动命令后，用户打开一个地址，首次设置所有者账号，登录进入中文控制台。页面展示服务连接状态和明确的空状态。

## 实施范围

1. 建立前后端目录、依赖锁文件、格式检查、类型检查和测试入口。先落实 docs/design 的 token、Element Plus 主题映射、公共组件展示页和工作台布局，再做业务页面。
2. 后端分离接口、领域、业务服务、数据访问；提供存活和就绪探针。数据库不可用时就绪检查必须失败。
3. 建立 Alembic 迁移，首次账号初始化必须原子化、仅能发生一次；不使用公开固定默认密码。
4. 实现单所有者认证、密码哈希、注销、会话过期、写请求保护。无权限请求返回统一错误。
5. Vue 建立导航：公司概览、组织、模型、项目任务、提案、审计；尚未实现页面展示空状态和用途。
6. Compose 包含 web、api、worker、postgres 和迁移步骤；worker 本阶段仅启动健康循环，不执行业务。
7. Web 统一代理 API，生产构建可用，内部数据库不默认暴露到公网。
8. 配置文件提供示例和说明；密钥不入库、不写日志、不提交 Git；数据使用持久卷。

## 验收

- 全新环境使用文档中的命令能够启动，前后端和数据库健康检查通过。
- 首次账号初始化成功；重复初始化被拒绝；错误密码不能登录；注销后旧会话失效。
- 未登录不能调用业务 API；跨站写请求不能绕过会话保护。
- 停止再启动服务，账号保留；重建容器后数据保留。
- 前端生产构建和后端基础测试通过；按 docs/quality-gates.md 完成三视口截图、按钮 32/40/48px 实测、登录键盘路径和颜色对比检查。
- 启动时迁移失败会明确阻止就绪，不出现“网页能开但数据库没初始化”的假健康。

## 交付与边界

交付 README、compose 配置、配置样例、锁文件、初始迁移、基础测试和阶段交接记录。此阶段不实现 Agent 推理、任务执行或提案审批。
