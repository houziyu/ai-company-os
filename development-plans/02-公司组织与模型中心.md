# 开发计划 02：公司模板、组织编辑器与模型中心

## 可直接交给 AI 的任务

请在阶段 01 工程基础上实施公司创建和配置。阅读总纲及上一阶段交接，保留现有登录与部署机制。

## 本阶段结果

用户在 Web 上创建默认科技公司，看到五岗位和五个独立 Agent，能修改员工资料、汇报关系与模型绑定，能配置和测试模型连接。

## 实施范围

1. 建立 Company、Department、Position、PositionVersion、Agent、Provider、Model、AgentModelAssignment。
2. 默认模板包含 CEO、产品经理、技术负责人/开发、QA、DevOps；模板实例化与公司数据分离。
3. 公司初始化向导：公司名、目标、模板、模型连接；允许先保存、稍后配置密钥。
4. 组织页展示部门、岗位、主管和员工；支持编辑名称、职责、主管、模型和启停状态。管理关系禁止环，不改变工具权限。
5. 分离岗位职责与实例覆盖字段；记录版本。更换模型、暂停员工不得删除身份与履历。
6. 模型中心分开管理 Provider、Model 和分配关系；初期支持一个 DeepSeek 预设和自定义兼容接口。
7. 定义统一模型适配接口，支持超时、结构化错误和 JSON 输出验证；不假设所有兼容模型能力完全相同。
8. 密钥先采用环境变量或 Compose secret 引用，界面只显示是否配置；配置并测试模型名称和 base URL。保存配置与联网探测分开。
9. 探测记录时间、结果和能力，标识可能消耗少量 Token；最多一次调用，不自动循环重试。登记独立用量记录，阶段 03 纳入统一预算。
10. 组织和模型配置变化写审计记录；不得将密钥或供应商完整错误响应返回页面。

## 验收

- 一次初始化生成且只生成五岗位、五实例；重复提交不会复制公司。
- 编辑岗位/员工/模型后刷新仍保留；循环汇报关系被服务端拒绝。
- 普通主管关系调整不增加资源操作权限。
- 模拟供应商测试覆盖：正常 JSON、错误密钥、超时、无效 JSON。
- 真实密钥缺失时明确显示未配置，不能显示连接成功或切换演练。
- 查询响应、数据库记录、日志和前端构建产物均不含实际密钥。

## 交付与边界

交付初始化向导、组织编辑器、模型中心、适配器协议、迁移及测试。完整招聘/调岗审批留到阶段 06；此时组织编辑均由所有者操作。
